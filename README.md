> **The goal: communication that is as close to instantaneous as physics allows, wherever the two ends are, and secure.**
> Physics sets the limit exactly. No signal outruns light, and entanglement does not change that: whatever one end does to its half of a shared pair, the other end sees nothing new until a classical message arrives. So "almost instantaneous" means one trip at the light-time floor with nothing waiting on top: routes that travel at nearly c, and key and entanglement banked before the message exists. On Earth that floor is at most 67 ms; to the Moon about 1.3 s; to Mars 3 to 22 minutes. This repository computes how close each route and protocol gets, what hardware could close the gap, and what a student can build on the way, in code where every formula is cited and every module has an analytic test.

> **Development status: experimental research software, not a production cryptographic system.** Numbers are model outputs unless a section says measured, and nothing here is a security-reviewed link; the [audit findings matrix](docs/audit/2026-10-11_findings.md) records what is fixed, tested, deferred, and blocked. The tests badge is written by the CI run that built the deployed website. Do not use simulated keys or the browser messenger for sensitive data.

## The goal: anywhere, at the speed of light

<p align="center"><a href="https://Normansrule.github.io/quantum-link-research/latency/"><img src="docs/figures/readme_latency.svg" alt="From Los Angeles to New York, London, Tokyo, Sydney, the Moon, and Mars: the light-time floor, the fastest route, terrestrial fiber, and a fresh TLS connection on a log-time axis" width="100%"></a></p>

Three things separate a message from the floor, and [`qll/space/latency_floor.py`](qll/space/latency_floor.py) computes each of them:

1. **The route.** Light in glass fiber moves at about 1/1.47 of c, and real cables wander from the great circle. Hollow-core fiber carries light at about 99.7 % of c; a low-orbit laser mesh climbs a few hundred kilometers and then travels in vacuum, which beats terrestrial fiber over long distances; a geostationary relay adds a quarter of a second. Between planets the straight line through free space is the only route, and it already sits on the floor.
2. **The handshake.** A fresh internet connection spends two round trips (TCP, then TLS 1.3) before the first byte of data, so the receiver reads the message after five one-way trips. Key made by QKD on demand needs three.
3. **The key.** Key banked in advance, from QKD sessions run earlier, lets the ciphertext leave at once: one trip, at the floor of that route. Teleportation behaves the same way with entanglement banked in memories: only the two classical bits travel. [`qll/link/banked_messenger.py`](qll/link/banked_messenger.py) runs this between two independent processes: with the Los Angeles to London delay of 35.4 ms, banked messages are read after 1.02 trips and messages keyed on demand after 3.06 ([how to run it](systems/program/10_anywhere_at_light_speed.md#running-l2-yourself)).

A one-time pad is information-theoretically secure only if its key is truly random, secret, used once, and paired with authentication, and it spends a key bit per message bit. AES-256 under a link key is estimated to keep about 128-bit security against known quantum attacks (Grover search) and keys millions of messages. Public-key messengers need no bank, but a recording can be decrypted later by a large quantum computer. That is why the Mars messenger banks key: at 22 minutes a trip, waiting for fresh key would cost another 44.

## What is implemented?

Implemented is not the same as tested, tested is not the same as measured, and measured is not the same as secure under a stated threat model.

| Component | Implemented | Tested | Measured | Security-reviewed |
|---|---|---|---|---|
| BB84 link pipeline: decoy states, Cascade reconciliation, privacy amplification, key accounting | Yes, simulation | Against closed-form models | No | No; finite-key length is a simplified estimate |
| Authentication and key lifecycle: OPEN/VERIFIED/FAILED channel, one-time key store, seeded simulation ledger or a secret byte pool | Yes | Sticky failure, sealed transcript, reuse, and atomicity tests | No | No |
| Two-site log workflow: strict per-site CSV parsing with SHA-256 provenance | Yes, offline analysis | Invalid-log regressions | Synthetic logs only, labelled synthetic | No |
| Classical transport: session-bound authenticated TCP (a lab construction) | Yes | Replay, reflection, timeout, and partial-frame tests on loopback | No | No; mutual TLS is the recommended replacement |

For the two-room experiment the paths are separate: **fiber Ethernet carries only the classical channel; the initial P10 quantum path is free space, inside an enclosed path between the rooms.** A bright-light polarization analogue is educational, not secure quantum key distribution (QKD).

## How the link fits together

```text
Site A                                         Site B
preparation / emission  -- quantum path -->    measurement / detection
        |                                              |
        +------- authenticated classical messages -----+
        |                                              |
        +-- parameter estimation and reconciliation ---+
        +-- verification and privacy amplification ----+
        |                                              |
 accepted key material                          accepted key material
        |                                              |
        +-------- application / key accounting --------+
```

This is a conceptual view. Each run labels which blocks are simulated, analyzed offline, or physically present: `python -m qll.link.run session` prints its execution mode, its execution identifier, and whether its authentication pool is a seeded simulation ledger. Authentication is required, and a low observed error rate alone does not prove that a finite key is secure.

## Which memory reaches Mars?

<p align="center"><img src="docs/figures/readme_timescales.svg" alt="How long each demonstrated quantum memory keeps teleportation above the classical limit, against round trips from metro fiber to Mars: three memories outlast Mars' farthest round trip" width="100%"></p>

This is the thesis question in one picture. A stored Bell pair decays toward the useless mixture while the two classical bits cross the Solar System; the bar is how long it stays useful. Hour-class trapped ions and rare-earth crystals clear Mars' farthest round trip, the rare-earth crystals only with a retrieval efficiency below 5 %. The lifetimes are the reported coherence times; the efficiencies are assumed operating points, not values measured together with those lifetimes, and a long spin coherence is not by itself a complete photonic memory. [`qll/network/memory_decoherence.py`](qll/network/memory_decoherence.py) computes it and [`learn/03_quantum_communication`](learn/03_quantum_communication) explains it.

## The argument in five equations

<p align="center"><img src="docs/figures/readme_equations.svg" alt="Five equations: thermal occupation, geometric beam loss, light-time delay, memory decay against the 2/3 teleportation limit, and the PLOB repeaterless bound" width="100%"></p>

<details>
<summary><b>The same equations as LaTeX</b></summary>

$$\bar n(\omega,T)=\frac{1}{e^{\hbar\omega/k_BT}-1}\qquad\text{heat decides where each part of the link can live}$$

$$\eta_{\rm geo}=1-\exp\left(-\frac{2r_{\rm rx}^2}{w(L)^2}\right),\qquad w(L)=w_0\sqrt{1+(L/z_R)^2}\qquad\text{photons are lost as }1/L^2\text{ in space}$$

$$\tau=\frac{d(t)}{c}\qquad\text{the two classical bits of every teleportation arrive minutes later}$$

$$f(t)=\tfrac14+\left(f_0-\tfrac14\right)e^{-t/T_{\rm mem}},\qquad \bar F=\frac{2f+1}{3}>\frac23\qquad\text{so the memory must outlive }2d/c$$

$$K\le-\log_2(1-\eta)\qquad\text{and no repeaterless protocol beats this}$$

</details>

## Systems engineering

<p align="center"><a href="https://Normansrule.github.io/quantum-link-research/systems/"><img src="docs/figures/site_systems.jpg" alt="The traceability page: needs, requirements, trades, risks, and the V model" width="100%"></a></p>

This is a systems-engineering thesis, and the repository is organized like a system. Five stakeholder needs ([`systems/needs.md`](systems/needs.md)) trace to the requirements in [`traceability_matrix.csv`](systems/traceability_matrix.csv), each with a verification method and the named test that verifies it; `python -m qll.systems.traceability` fails if a test or test function is missing, and the requirements document ([`systems/requirements.md`](systems/requirements.md)) is generated from the matrix. The [traceability page](https://Normansrule.github.io/quantum-link-research/systems/) puts it all on a V model you can filter.

### The two-site key link (SEE 510 case study)

[`systems/see510/`](systems/see510/README.md) takes flagship F1 down to a laboratory key link between Site A and Site B and simulates it end to end:

- BB84 states from an ideal single-photon source or an attenuated laser with decoy states, through a fiber of configurable length;
- detectors with finite efficiency and dark counts;
- two textbook adversaries: intercept-and-resend, and photon-number splitting on a laser source;
- Cascade error correction with hash verification, and privacy amplification;
- a classical channel authenticated with Wegman–Carter tags that fails closed and stays failed; in simulation a seeded ledger stands in for the authentication key, while a secret pool consumes real bytes and is replenished only from accepted key with recorded provenance;
- key delivery to an AES-256-GCM demonstration application through an ETSI GS QKD 014-style interface.

Twelve validation cases match closed-form models, and every run reproduces from its configuration and seed. A [real-world ladder](systems/see510/10_real_world_experiments.md) builds it in five tiers, from a $40–120 Arduino-and-polarizer analogue through fiber characterization and single-photon BB84 to entanglement-based BBM92. Each tier's log runs through the same protocol code with `python -m qll.link.run ingest`. Fifteen stakeholder needs trace to modules, tests, and [evidence](systems/see510/evidence/README.md). `python -m qll.link.run scenarios` regenerates the evidence in about 45 seconds. A scripted [operations day](systems/see510/evidence/operations/README.md) runs 96 sessions through drift, interception, a fiber bend, tampering, and a fiber cut; the [operations console](https://normansrule.github.io/quantum-link-research/link/) replays it, and shows the link failing closed during the cut.

### The mission: from two rooms to orbit

[`systems/program/`](systems/program/README.md) turns the research into one phased plan, with gates, three-point costs, a critical-path schedule, a risk register, trade studies, and a path to a company:

1. **Phase 1, two rooms (planning estimate: about $690 likely).** A fiber classical channel between two rooms. Single-photon BB84 with decoys through an enclosed free-space path, using four silicon photomultipliers ([P10](experiments/protocols/P10_two_room_single_photon_link.md)), compared line by line with a planning model; blocked until a qualified safety review is recorded ([evaluation specification](experiments/specs/two_room_evaluation_spec.md)). The collapse code on a free cloud processor ([P11](experiments/protocols/P11_collapse_code_on_a_cloud_processor.md)): a bound, to be measured, on whether the way a shared state collapses can carry a message (quantum mechanics says it carries none).
2. **Phase 2, entanglement between the rooms.** A borrowed source, a Bell test, an entanglement-based key, and superdense coding through the hallway: more than one bit per photon ([E19](experiments/proposed/E19_superdense_coding_through_the_hallway.md)).
3. **Phase 3, outdoors and toward orbit.** Free space between roofs and buildings, a ground station, and a satellite only with a partner. The [outdoor lab](https://normansrule.github.io/quantum-link-research/lab/outdoor/) shows what to expect: the SiPMs of P10 make no key outdoors, avalanche-diode modules reach about 2 km at night, daylight swamps a 405 nm receiver, and a Micius-class pass loses 26–39 dB ([`qll/link/outdoor_link.py`](qll/link/outdoor_link.py), [`qll/link/satellite_pass.py`](qll/link/satellite_pass.py)).
4. **Phase 4, the frontier.** Entanglement-assisted communication: teleportation and superdense coding, each with its classical channel. The first step is free: teleportation on a cloud processor with the two bits delayed, whose fidelity follows the qubit's own T₁ and T₂ down through 2/3 after about 110 µs ([E01](experiments/proposed/E01_delayed_classical_channel_teleportation.md)). The [frontier lab](https://normansrule.github.io/quantum-link-research/lab/frontier/) carries the same timing to a swapping node, the rooms, and Mars ([`qll/network/teleport_across.py`](qll/network/teleport_across.py)).

**The application.** [P15](experiments/protocols/P15_messages_keyed_by_the_link.md) spends the link's key on messages and measures how many a day each link can key and how big a key bank keeps the messenger from refusing ([`qll/link/keyed_messaging.py`](qll/link/keyed_messaging.py)); the [messenger lab](https://normansrule.github.io/quantum-link-research/lab/messenger/) does it live in the browser.

**Quantum channels.** The hallway already carries qubits, not just key bits. [P14](experiments/protocols/P14_the_hallway_as_a_quantum_channel.md) certifies it as a quantum channel from the BB84 counts within a trusted qubit model (no classical relay could match them), maps it by process tomography with two $10 quarter-wave plates, and computes what it can carry; the same analysis shows that teleportation is a quantum channel only with its two classical bits ([09](systems/program/09_quantum_channels.md)).

Every experiment already in the repository is catalogued with the phase it feeds and what it takes to replicate it ([02](systems/program/02_research_foundation.md)). The [lab](https://normansrule.github.io/quantum-link-research/lab/) lists all of them and opens the ones with a build in 3D, from a starter to the real-world option ([`qll/systems/lab_scenes.py`](qll/systems/lab_scenes.py)).

## Run a simulation

The supported environment is Python 3.12 in the pinned Conda environment, on Linux or Windows (CI runs both). From a checkout:

```bash
git clone https://github.com/Normansrule/quantum-link-research.git
cd quantum-link-research
conda env create -f environment.yml
conda activate qll
python scripts/check_env.py
python -m qll.link.run session
```

The session prints the configuration, the observed errors, the acceptance decision, and the modelled key accounting. A reproducible seed helps debugging; it is **not a source of secret entropy**.

```bash
python -m qll.link.run validate          # exits 1 if any validation check fails
python -m pytest -q -m "phase1 and not slow"
python -m pytest -q -m "not slow"        # the broad suite
python -m pytest -q -m browser           # headless Chromium: pip install playwright && python -m playwright install chromium
```

Locally, a missing optional tool (Node.js, Chromium, an optional simulator) skips its tests. In CI, each job lists what it requires in `QLL_REQUIRE`, and a skip for a required tool fails the job ([`tests/conftest.py`](tests/conftest.py)).

## Build the two-room experiment

Begin with the simulation and the classical transport, then a controlled polarization analogue, then detector and source characterization. Read [P10](experiments/protocols/P10_two_room_single_photon_link.md) as a planning document: its build status is **BLOCKED** until a qualified review of the actual source, accessible emissions, and alignment is recorded in the [evaluation specification](experiments/specs/two_room_evaluation_spec.md). Never route an exposed beam through a hallway or other occupied space, and never treat a nominal attenuator setting as proof of safety.

Do not buy the whole hardware list before checking detector noise, timing, the optical-loss budget, available instruments, and a safe test arrangement. Record source type, calibration, uncertainty, instrument and firmware identifiers, and raw per-site logs, and label every result **synthetic**, **analogue**, or **single-photon experimental data**. A positive acceptance decision in the simulation does not promote a measured run to a secure implementation. The [bill of materials and build order](#build-the-main-experiment-phase-1) close this page.

## Build the main experiment: Phase 1

The main experiment is [P10](experiments/protocols/P10_two_room_single_photon_link.md): single photons between two rooms. Weak 405 nm pulses at about half a photon each carry four polarizations through an enclosed free-space path between the rooms, decoy pulses guard against photon-number attacks, and four silicon photomultipliers read them in the other room. A separate fiber Ethernet link carries only the classical channel. The planning model predicts a click on 5.85 % of pulses, an error rate of 3.7 %, and about 12,000 test-key bits from each ten-second session; these are model outputs, not measurements, and the key would have no security review. The [link lab](https://normansrule.github.io/quantum-link-research/lab/link/#two_room) shows every part in 3D at the price below.

## Scale the Majorana research: from one hop to a chain

Crogman, Dang, and Erenso (2025) teleport a qubit between Majorana-encoded qubits using joint parity measurements alone. The repository emulates their protocol on a free cloud processor, then scales it from one hop to a chain of hops. Each hop is the same local Bell measurement wherever it sits in the chain, because the Jordan–Wigner strings of neighbouring modes cancel, and each hop needs its own two classical bits. The chain's fidelity falls as $F_N = \tfrac12(1 + k\,s^N)$, and the paper's error budget turns a target chain length into a requirement on the device.

| Step | What | Hardware | Cost | Status |
|---|---|---|---|---|
| 1. [P13](experiments/protocols/P13_majorana_teleportation_on_a_cloud_processor.md) (M4.6) | The paper's protocol, one hop: two parity bits against one | 3 qubits on a free cloud processor | $0 | device-copy rehearsal: 0.835 with two bits, 0.641 with one; hardware run next |
| 2. [E20](experiments/proposed/E20_majorana_parity_teleportation_chain.md) (M4.8) | The same protocol along 1, 2, 3, … hops; fit the loss per hop | 2N + 1 qubits in a line | $0 | device-copy rehearsal: 0.837, 0.797, 0.796 for 1–3 hops; *s* ≈ 0.94, *k* ≈ 0.70, about 11 hops above 2/3; hardware run next |
| 3. Device requirement | Readout and poisoning a chain of N hops needs | the error budget | $0 | table below |
| 4. Tetron devices | Four Majorana modes per qubit at fixed parity, with the CSUDH authors and a device group | a partner's dilution refrigerator | outside funding | research version of E18 and E20 |

**What a Majorana chain needs.** Assume a gap Δ/*kT* = 5, poisoning 0.001 per readout window, and *L*/ξ = 6. The table gives the smallest parity-readout signal-to-noise ratio μ₀/σ that keeps the chain above each fidelity:

| Hops | Above 2/3 | Above 0.9 | Above 0.99 |
|---|---|---|---|
| 1 | 0.92 | 1.66 | 2.65 |
| 4 | 1.56 | 2.25 | 3.21 |
| 16 | 2.17 | 2.79 | not reachable |
| 64 | 2.71 | 3.42 | not reachable |
| 128 | 2.98 | not reachable | not reachable |

Where a cell says "not reachable", poisoning alone caps every hop and no readout can compensate. Scaling the protocol therefore asks first for longer quasiparticle-poisoning times, and only then for better readout.

python experiments/bench/frontier/run_frontier.py chain --backend aer --hops 1 2 3            # the chain (E20)
python experiments/bench/frontier/run_frontier.py chain --backend ibm_torino --layout 0 1 2 3 4 5 6 7 8 --hops 1 2 3 4
