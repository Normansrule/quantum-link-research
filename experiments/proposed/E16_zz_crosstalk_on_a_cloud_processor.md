# E16 — Measure ZZ crosstalk on a cloud quantum processor

**Gap.** Learn 02/22 computes the static ZZ between two transmons and the idle point where a tunable coupler cancels it, and `qll/hardware/cz_gate.py` simulates the gate that uses the same interaction. None of it has touched a real device. The ZZ that vendors publish is a summary number; how it varies across a chip, and between a fixed-coupling and a tunable-coupler processor, is something a student can measure directly for free.

**Question.** For every neighbouring pair on one open-access processor, what is the static ZZ, how is it distributed, and does it match the processor's architecture: tens of kilohertz or more for fixed couplings, near zero for tunable couplers parked at their idle point?

**Cheap version (software + free cloud time).** Build the conditional-Ramsey circuits with `qll.circuits.zz_ramsey.ramsey_circuit(tau, neighbor_excited, detuning)` (hardware mode uses `delay` instructions), 60 delays from 0 to 30 µs, two neighbour states, 2 000 shots each, on a device reachable under a free plan (for example IBM Quantum Platform's open plan; check the current allowance and use Qiskit's session batching). Fit with `measure_zz`. The whole pipeline is tested against injected ZZ in Qiskit Aer first (`tests/test_zz_ramsey.py`): it recovers ±50–80 kHz to within 1.5 kHz and the coupler model's ZZ to within 3 %. Before trusting a sign, run one pair twice with the virtual detuning's sign flipped: the vendor's `rz` convention decides which fringe is which.

**Research version.** Joint amplification of ZZ (echoed sequences on both qubits) to reach the sub-kilohertz ZZ of tunable-coupler devices; map ZZ against the reported qubit frequencies and anharmonicities and fit the coupling with `static_zz_exact`; repeat daily to see drift. Then the gate: interleaved randomized benchmarking of the native two-qubit gate (`qll/circuits/benchmarking.py`) against the coherent-error floor that `cz_gate.py` predicts.

**Physics it would settle.** Whether the Duffing-oscillator model of learn 02/22 predicts real-device ZZ from published parameters, and how large the always-on phase error of an idle superconducting processor node would be over the milliseconds a network protocol keeps it waiting.

**Verifies.** No link-level requirement yet; it calibrates the processor-node error budget used in the E7 and E8 trade studies and would support a new requirement on idle crosstalk for any superconducting node.
